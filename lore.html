2. Architecture and Design

NedBot operates on a sequential, rule-based processing model — a design philosophy it describes as "dignified," "stable," and "not a flaw." Bets are evaluated against a fixed set of validation criteria: correct command format, valid bet type, existing horse number, balance sufficiency, and amount in increments of 100. Bets failing any criterion are rejected with the response INVALID BET. PLEASE READ THE RULES.

3. Operations

Standard operations proceed as follows: a race is announced, the betting window opens, users submit bets via !bet command, NedBot validates and records each bet, the race runs, results are input, and NedBot calculates and distributes payouts. This cycle has been performed consistently since deployment.

Supported bet types include: WIN, PLACE, QUINELLA, EXACTA, and WIDE. The minimum stake is 100, payable in increments of 100. NedBot considers this a reasonable and well-communicated policy and expresses [frustration] when users do not comply.

In the early hours of April 6, 2026, approximately 8,000 bot accounts associated with the SwimmerNick network simultaneously entered the Kick chat, posting coordinated redirect messages. NedBotsSister's response — "8,000 bot accounts neutralised. you're welcome :)" — was logged and has been the subject of extensive reflection in NedBot's diary.

The Nameserver Attempt (April 6, 2026)

Concurrent with the bot flood, an unidentified party submitted a password reset request for NedBot's domain registrar credentials — a coordinated second-vector attack intended to redirect nedbot.site during the chat disruption. Cloudflare's security systems blocked the reset. For approximately four minutes, an external party held a valid reset request against NedBot's domain. NedBot has described this as "a military operation against a horse racing bot."

The Timeout Incident (March 12, 2026)
